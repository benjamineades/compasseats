Venue name casing — site-wide all-caps cleanup

MediumLarger

418 venues have ALL-CAPS names across nearly every source tab — Michelin Guide (210), Restaurant Awards (109), Best Chef (74), plus OAD/Pinnacle/James Beard/etc. They display shouting on cards ("THE EIGHTY SIX", "APONIENTE", "SÉZANNE"). Local-currency price tiers (proper fix in sync-sheet.ts)

MediumSchema change

Goal: let each venue display its local currency — Paris €€€, Tokyo ¥¥¥, London £££, US $$$ — instead of flattening to dollar signs. More on-brand, and it stops non-dollar source data (Michelin's European €€€€) from failing schema validation.

Approach (decided): store price as a tier number 1–4 plus optional currency symbol, not an overloaded dollar string. Sync normalizes any source glyph (€€€, ¥¥, £££) into e.g. { price_tier: 3, price_currency: "€" }; display renders tier copies of currency; sort/filter uses the numeric tier. Rejected: allowing €/¥/£ as extra valid strings — fragments data, pushes equivalence logic into every consumer.

Breaking schema change — coordinated edits: (1) schema.ts — price_tier → z.number().int().min(1).max(4) + optional price_currency; (2) sync-sheet.ts rowToVenue — parse string → tier+currency; (3) every price display (card + venue-page badge). Interim (live now): the JSON generator normalizes €→$ so data validates and the site shows universal $$$$ — fine to leave until this lands.
