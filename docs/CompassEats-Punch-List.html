SHIPPED — Reshape's name-only geo fallback creates cross-continent identity collisions

ShippedJuly 19

preflightPublish caught 10 duplicate city/slug pairs; 3 turned out to be two completely different real venues sharing one row. Confirmed by web search against primary sources: The River Café (Michelin-starred in both London and Brooklyn — Brooklyn's OAD/award data was sitting on London's row), Miura (a 2026 Michelin star in Beverly Hills vs. the unrelated Miura Hotel in Čeladná, Czechia), and Amano (Bib Gourmand vs. a James Beard-nominated, unrelated Amano in Caldwell, Idaho — see below, this one resolved differently than expected). Root cause: reshape falls back to name-only geo matching when a name+city lookup misses, and when two unrelated venues share a name, the fallback can silently attach one's award data to the other's place_id.

Not every duplicate was this bug: 7 of the 10 gate failures resolved live July 18 — 4 were true duplicates (same venue split across two award-source rows, awards unioned, conflicting stray ranks dropped in favor of the authoritative entry) and 3 were plain data errors, not collisions (Aoyama Sushi Umi's "Panama" row belonged to an unrelated restaurant called Umi, ranked separately on Latin America's 50 Best; Doma's "US" row was a phantom with no real second venue; Chengdu's Yu Zhi Lan had one row with a stale one-star rating — Michelin's own 2026 announcement confirms it's held two stars continuously since 2022).

Final 3 resolved July 19 — no paid API spend needed. The ~$0.10 Places lookup flagged as a blocker turned out to be unnecessary: Google place_ids are global, not tied to the requesting key, so all three were looked up for free via a Places tool already available in chat. River Café re-pinned to Brooklyn, folded into the existing new-york city (1 Water St, Brooklyn). MIURA re-pinned to Beverly Hills, folded into los-angeles (218 N Rodeo Dr), cuisine corrected to Japanese. Amano turned out not to be a simple relocation: New Zealand's first-ever Michelin Guide (published July 1, 2026 — after Claude's training cutoff, confirmed via live search) awarded its Bib Gourmand to A'mano in Christchurch, not Auckland's unrelated Amano — the ingest had matched the wrong venue on a substring, the same failure class as the earlier Aoyama Sushi Umi bug. Auckland's Amano carries no real accolade under either name, so rather than relocate the row there, it was reattributed to Christchurch's A'mano (Ben's call), correctly crediting the actual awardee and dropping the unawarded Auckland venue from the dataset. All three verified via a read-only Apps Script audit before the fix, applied via a dry-run-then-live script (0 blocked, 0 collisions), confirmed clean in preflightPublish (0 duplicate keys, 0 orphan cities), then carried through JSON regen → GitHub commit → Lovable publish → live spot-check on all three pages. Contaminated blurbs on the 3 rows were deliberately blanked rather than left showing the wrong city's copy — see new Pipeline item for the follow-up.

Worth a broader look eventually: this only surfaced because these 10 happened to share a slug — the same failure mode likely exists silently elsewhere in the 10,844-row dataset. A durable fix (e.g. requiring a country/region match, not name-only, before reshape's geo fallback accepts a match) would be better than patching instances as they're found. Not yet scheduled.
