01Visual language locked this sprint

The two-surface system

CompassEats now uses a deliberate dark-for-moments / paper-for-detail system, not a uniform dark site:

  • Dark surfaces (warm charcoal #23211E): homepage, city hero/skyline, spotlight band, all hero imagery, footer.
  • Light editorial surfaces (warm paper #F7F3EB): the venue detail body, the Cities index (/cities), the Guides index (/guides), and the paper bands of the city page (map + ranked list). Dark heroes, paper reading surfaces — now applied consistently across every major surface.

Critical implementation note. The paper venue body uses explicit fixed hex values, NOT theme tokens, so it stays paper even when the site is in dark mode (the default). In dark mode --accent-strong collapses to brass and --background is charcoal — relying on those would break the light look. Fixed values for paper sections: bg #F7F3EB, ink #23211E, muted ink #6a6253, bronze accent #895F2E, brass #C6A15B, card fill #FCFAF5, hairline rgba(35,33,30,.12).

The compass mark & motion

  • Mark: two concentric rings, four cardinal tick marks, a two-tone needle (brass north #C6A15B / bronze south), Fraunces N/E/S/W letters just outside the outer ring (N italic, emphasis).
  • Motion (Option A — full face spins): rings + ticks + letters all rotate together, 50s linear; needle + center pivot stay fixed. On hover: spin pauses and the dial settles to N-up over ~2.6s cubic-bezier(.22,.7,.2,1). Honors prefers-reduced-motion (static N-up).
  • Header lockup is wordmark text only — no compass icon in the header (one compass per page). Footer keeps its compass.

Homepage hero background

  • Top-sourced warm glow (originates above the viewport, fades downward — "light over a horizon"), over a large-cell nautical-chart grid (110px cells, ~5% brass opacity), masked so the center stays clear and edges fade.
  • Corner coordinates in Fraunces at ~12% opacity. Homepage = fixed Atlanta HQ (33°45′N · 84°23′W · ATL). City pages show that city's real coordinates (dynamic, from geocoded city data). Spotlight band carries a single faint city coordinate, no grid.

Typography & color

  • Fraunces (display serif, light weights + italic) for headings/marks; Hanken Grotesk (sans) for body.
  • Brass #C6A15B = fills/buttons (both modes). Bronze #895F2E = accent TEXT on light surfaces only (collapses to brass in dark).

Interaction standard

Global: --ease-standard: cubic-bezier(.4,0,.2,1), --dur: 150ms, an .interactive utility (hover lift translateY(-2px) / press scale(.98), reduced-motion guarded). Never applied to MapLibre marker root elements — hover affordances go on an inner child so MapLibre's positioning transform is preserved (this caused the pin-jump bug).

02Award badge logic

The pill/badge label helper awardLabel(award) (and awardLabelShort) in src/lib/award-label.ts drives the standalone pills — ranked rows, city spotlight, city venue cards, related-venue cards. Two other surfaces build their own labels deliberately: the venue detail accolade cards use a local distinctionLabel (the source name is already shown separately in each card header, so the distinction stays bare, e.g. "★★" under a "Michelin Guide" header), and map popups are hand-built in VenueMap. When changing a label format (e.g. the Michelin "★★ Michelin" change), update award-label.ts AND the VenueMap popup builder to keep all surfaces consistent — the detail-page cards are intentionally separate. All powered by venue.awards (parsed Award[] of {source, year, category, rank?} — 100% populated, no data work needed).

03Page-by-page state

Homepage Done

  • Hero: spinning lettered compass, eyebrow "The world's best, wherever you are", H1 "Eat and drink well, anywhere on earth." (no longer the brand name; no self-link), subhead, search + "Find the best →" + "Use my location instead" (brass + locator icon).

  • Explore by guide: "Browse the source" eyebrow + "Explore by guide" (italic brass), ruled list sourced from AWARD_SOURCES registry, counts shown only if real.

City page Done src/routes/city.$slug.tsx

  • Two modes by venue count, both on the fixed-hex two-surface system (migrated off semantic theme tokens June 6 — the last major surface to move). Single-venue (75% of cities): dark hero → dark feature band (one generous venue: photo + name + awards-derived "why" + pills + CTAs; centered single-column only when no photo can be found, so no empty box; June 21: the feature now passes placeId to VenuePhoto, so single-venue cities pull a live photo and the centered layout is just the rare fallback) → paper map band → paper "explore other cities" outro. Multi-venue: dark hero → dark CitySpotlight band → paper map band → "The ones worth the detour" headline + segmented All/Restaurants/Cocktail Bars toggle → ranked list. AwardMarquee removed from the city page.
  • Hero carries an in-hero breadcrumb (Home › Country › City) above the headline and a per-city counts line below ("23 charted spots · 22 restaurants · 1 bar" — correctly pluralized, computed from loaded venues, restaurant/bar split by type).
  • Spotlight: rotating soft opener, photographed-first featured pick (falls back to top-prestige + compass placeholder when no venue has a photo, hiding "Show me another" when there's nothing to rotate to), single faint city coordinate. The "why" uses an awards-derived fallback when blurb_short is absent ("Two Michelin stars and a World's 50 Best ranking — one of {city}'s most decorated addresses") — the old bland "A charted favorite in {city}" fallback is gone. "Open now" logic built but dormant (auto-activates when hours data lands).
  • Map above filters in a bronze-eyebrow paper band, framed (rounded + hairline); reuses VenueMap; pins filter with the filter bar (venues={filtered}). Ranked rows: bronze numerals, name in solid ink (legible on paper), type · neighborhood, price when present, bronze-outline pills. List capped at 50 with "Show all N" expander.

City hero — photo cascade & compass title-card fallback Done src/components/CityHero.tsx

  • The banner resolves a real photo before it ever falls back. Order: stored hero_image_url (none today) → Wikipedia summary by name, trusted only if its coordinates sit within ~80 km of the city's real lat/lng (the geo-proximity guard — stops "Savannah"→grassland-savanna biome and every other ambiguous-name mismatch) → Wikipedia geosearch by coordinates (catches small towns the name alone can't — Brusaporto, Chagny) → the compass title-card below. Wikipedia is free, so heroes add no Google cost. The route passes city, country, lat, lng to both call sites.
  • Compass title-card fallback (the no-photo state) — a deliberate title card, never an empty gradient. Base: a warm charcoal gradient linear-gradient(135deg, hsl(32 52% 21%) → hsl(24 46% 12%)) with the homepage compass rose set faintly behind the city name (brass #C6A15B, ~0.20 opacity; rings + cardinal ticks + N/E/S/W + two-tone needle, static N-up). A horizontal veil eases the warm color off by ~50% toward the compass on the right (linear-gradient(to right, rgba(19,17,15,0) 20% → .50 95%)) so the title keeps a full-warm pocket on the left and the compass sits in a calmer one on the right.
  • Shared composition. Both states keep the dotted texture (~0.14 opacity), the in-hero breadcrumb + counts, and white text. Over a real photo a top→bottom black wash (70→40%) preserves legibility; that wash is suppressed on the fallback so the warm card reads true.

Venue page Done src/routes/venue/$city/$slug.tsx

  • Dark photo hero (VenuePhoto with charcoal+compass fallback), place line above name (larger than eyebrow, smaller than H1), meta line leads with price.
  • Light paper body (editorial). "Why we point you here" pull-quote + prose (blurb fallbacks). Collapsible per-source accolades with star glyphs.
  • Sidebar: white card, actions on top (Reserve / Visit website, shown only when URL exists), facts list. No Chef row (field not in data).

04Data reality (what's empty)

All pages degrade gracefully; the site works everywhere but only sings where data exists. Current fill on the venues tab (~9,226 venues):

  • awards — 100% ✓ (badges + accolades fully powered)
  • photo_url — ~43% (over half show the charcoal/compass hero fallback)
  • blurb_short / blurb_long — 0% (spotlights & venue pages show fallback lines)
  • price_tier, hours, reservation_url, website, neighborhood — 0%
  • chef — field does not exist in schema (would be net-new)

The schema is ready for all of it — venue.hours is even a pre-parsed object, so "open now" lights up the moment hours are populated, no rebuild.

06The big content unlock: blurb batch

Highest-leverage remaining work — fills the single most visible gap across spotlight, city cards, AND venue pages. Approach deliberately: draft the voice/prompt template first (grounded in brand vocabulary — charted, point you to, worth the detour; never "curated experiences" or "top 10"), test on ~10 varied venues, review together, THEN scale to ~9,200. Generated once, stored in the Sheet (blurb_short/blurb_long) so pages stay static and fast. A bad pass at scale is expensive to redo — voice matters more than plumbing.

07Working method (keep doing this)

  • Diagnostic-first prompts: have Lovable investigate & report (real file/token/component names) BEFORE writing changes. Guessing blind caused repeated misses (the compass grouping especially).
  • Full drop-in file replacements, not partial diffs (Ben applies via Lovable).
  • One build step at a time, verify (screenshot) before the next. Tightly-scoped prompts that say "currently shows X → change to Y" land better than "match the mockup" (Lovable can't see mockups).
  • Single source of truth: AWARD_SOURCES in schema.ts drives all guide labels everywhere.
