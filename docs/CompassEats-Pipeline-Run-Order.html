Pipeline Run Order

Version 1.0 Updated June 16, 2026 Owner Ben Status Canonical

The Apps Script panel lists the tools but not the sequence — and the sequence is load-bearing. Run this start-to-finish whenever Sheet data, matching logic, or CITY_ALIASES_ changes. Out-of-order runs produce stale or corrupt data (e.g. blurbs wiped, orphan cities, awards bound to the wrong row). Companion to the Data Pipeline & Publish Reference, which explains why publishing is manual on this plan.

AApps Script stage — the Sheet

Six functions, in this exact order. Each runs in the one "Compass Eats" project; they share globals, so the order they fire in matters.

1

reshapeCompassEats

Rebuilds the venues tab from the award source tabs + Places Enrichment. Applies CITY_ALIASES_ (suburb/fold relabels), unions awards for same identity (normKey + city), reads geo by name|city then name-only fallback.

⚠ Rewrites the tab from scratch — wipes blurb_short / blurb_long. That's why the blurb imports must follow. Log: ALIAS KEYS AT RUNTIME + venue total.

2

mergeDuplicateVenues

Collapses rows sharing place_id + city_slug + type, unioning their awards. Same place_id across different cities is sent to the merge_review tab, never auto-merged.

Must run after reshape (operates on freshly-built rows). Log: merge groups collapsed, rows removed, merge_review count.

3

importBlurbsFromDrive

Reads blurbs_final.csv from Drive and fills blurb_short / blurb_long, matching on slug only.

Repopulates what reshape wiped. Slug-keyed, so city folds/merges don't break the match. Log: "Filled blurbs on N rows" (expect ~10,200+).

4

clearWrongCityBlurbs

Clears blurbs that landed on secondary / mis-geocoded rows that share a slug with the flagship.

Runs before Option B because importOptionB matches by slug only and can otherwise write the premium blurb onto the wrong row. This clears the field first so Option B lands clean.

5

importOptionB

Writes the verified, hand-built Option B premium blurbs over the generic ones for the marquee set.

Last blurb step so its text wins. Slug-matched. Log: Option B rows written.

6

generateCitiesTab

Rebuilds the cities tab from the venues' current city_slugs — creates any new fold-target city, drops emptied ones, auto-fills country_code, sets lat/lng to each city's venue centroid.

Mandatory after any city_slug change (folds, aliases). Skip it and the build fails the orphan-city check (every venue's city_slug must have a cities-tab row). Log: cities count.

Gate — preflightPublish. Read-only check that mirrors the two build-fatal rules in sync-sheet.ts: duplicate city/slug keys and orphan city_slugs. Both must read 0 before regenerating JSON. Cheap insurance against a failed deploy.

BPublish stage — the repo

The build-time Sheet sync can't run on this plan (Build Secrets are Enterprise-only), so JSON is regenerated from a Sheet export and committed by hand. See the Data Pipeline doc for the root cause.

7

Regenerate JSON

File → Download → Microsoft Excel (.xlsx), then run it through the sync transform to produce venues.json, cities.json, venues-index.json. This is the same validation the build would run — it trims the export's blank padding rows, normalizes euro price_tier values to $-tiers, and fails loudly on any bad row (missing lat/lng, unknown award source, bad country_code).

Always sanity-check the new venues.json against the committed one before shipping: venue count, and blurb_long coverage (~10,200+). A sudden blurb drop to zero means a blurb step was skipped.

8

Upload to GitHub

Repo → data folder → Add file → Upload files → drag all three .json in (exact same names overwrite) → commit to main. All three are well under the 25 MB web limit.

9

Publish

Trigger the Lovable build. It reads the newly committed JSON and prerenders every /city/… and /venue/… page. Expect the SYNC SKIPPED banner — that's normal here; the committed JSON is the source.

Spot-check 3–4 fixed venues on the live site afterward (correct city, stars/awards rendering).

CBuild gates to remember fail = no deploy

  • Duplicate city/slug keys — two active venues can't share one.
  • Orphan city_slug — every venue's city must exist in the cities tab (run generateCitiesTab).
  • price_tier — only $ $$ $$$ $$$$ or blank; euros are normalized at JSON regen, but the Sheet still holds € until scrubbed.
  • Every venue needs numeric lat + lng, and every award source must be one of the 25 registered slugs.
  • City country_code exactly 2 letters; any hero_image_url must be a valid URL.

When in doubt: if a change is right in the Sheet but wrong on the site, the JSON wasn't regenerated and re-committed. The Sheet is never read live in production.
